## Phase Goal

**As a** Admin einer Nextcloud-Instanz, **I want to** dass die App auf meiner Hardware das beste sicher lauffähige Profil vorschlägt, nie mehr Speicher nimmt als sicher vorhanden, mit meiner Thread-Grenze und in meinem Zeitfenster rechnet und ihre Modelle nachprüfbar oder offline bezieht, **so that** Nextcloud und Datenbank nie unter der Transkription leiden und nichts ungewollt den Server verlässt.

<objective>
D-05-11: Die Thread-Zahl kommt in die Herkunft. Weil der Admin Threads senken darf und 1 und 2 Threads möglicherweise andere Wörter liefern (CI-Messung Plan 05-20), muss jede Version sagen, mit wie vielen Threads sie entstand. Anzeige in der UI ist nicht Teil der Phase (UI-SPEC).
</objective>

<feature>
  <name>Thread-Zahl in der Herkunft</name>
  <files>siehe files_modified</files>
  <behavior>
    - validate: engine "sample" mit threads != 0 -> ValueError("threads"); andere Engine mit threads < 1 oder > 256 oder nicht int -> ValueError("threads").
    - order_key unverändert; zwei Versionen, die sich nur in threads unterscheiden, sind gleichrangig (Tie -> stale wie bisher).
    - v4-Datei -> v5 mit transcript.threads; vorhandene parakeet-Zeilen bekommen den Wert 2 (Spike-3/Phase-3-Wert RECOGNIZER_THREADS, so gerechnet), sample-Zeilen 0; Fehler in der Mitte -> Datei bleibt v4 (Muster test_store_migration_v4).
    - publish_version schreibt threads; Lesen gibt threads zurück.
    - Preview-Job: Fake-Engine bekommt genau einmal use_threads(N) vor dem ersten Stück; Provenance.threads == N.
  </behavior>
  <implementation>
    Provenance um `threads: int` erweitern (letztes Feld, kein Default). schema.sql: Spalte `threads INTEGER NOT NULL CHECK (threads >= 0)`. `SCHEMA_VERSION = 5`, `migrate_v4_to_v5` mit `ALTER TABLE transcript ADD COLUMN threads INTEGER NOT NULL DEFAULT 0` und `UPDATE transcript SET threads = 2 WHERE engine = 'parakeet'` in einer Transaktion, Kopfkommentar "v4 to v5 (phase 5, plan 05-11, D-05-11)". sample.py: `threads=0`. preview.py: vor dem Chunk-Loop `n = self._threads_for_job()`, `engine.use_threads(n)`, `Provenance(..., threads=n)`; Engine-Protocol um `use_threads` ergänzen. child.py: `use_threads` laut Interface. Fakes in Tests anpassen.
  </implementation>
</feature>
