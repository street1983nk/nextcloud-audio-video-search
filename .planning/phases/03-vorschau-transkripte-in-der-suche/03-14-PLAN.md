  <behavior>
    Antwortregeln von /excerpt (eine Zeile je Fall als parametrisierter Test):
    - unbekannte fileId -> {"known": false}
    - Verweis unreadable, vanished, trashed (jeweils mit fertigem Transkript und mit Grund no_speech) -> genau {"known": false}; JSON-Bytes gleich dem unbekannten Fall
    - aktiv, current PREVIEW, Job complete, Wort an atMs -> {"known": true, "excerpt": "...", "stage": "preview", "partial": false, "pendingHere": false, "reason": null}
    - aktiv, Job running, chunks_done 1, next_start_ms 600000, atMs 300000 -> excerpt gesetzt, partial true, pendingHere false
    - dasselbe mit atMs 900000 -> excerpt null, partial true, pendingHere true (A4)
    - aktiv, Job queued ohne Stück, kein current -> {"known": true, "excerpt": null, "stage": null, "partial": false, "pendingHere": false, "reason": null} (A5)
    - aktiv, Job skipped no_speech -> reason "no_speech", excerpt null (A6); ebenso damaged, protected, unsupported_language, engine_failed, no_audio, format_unsupported
    - aktiv, Job skipped too_long -> reason "too_long", "limitHours": max_duration_hours() (A10); limitHours fehlt bei allen anderen Gründen
    - aktiv, Job waiting disk_full -> reason "disk_full" (A13)
    - Probe ohne echtes Transkript -> stage "sample", Verhalten wie heute
    occ: Preview-Zeile listet z. B. "complete 3, no_speech 1, queued 2"; --json enthält byPreview; keine Zeile enthält eine file_id oder einen Pfad.
  </behavior>
