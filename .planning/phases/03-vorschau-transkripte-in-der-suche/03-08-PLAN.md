<feature>
  <name>Stufen-Folge mit Offset und Stufe je Treffer</name>
  <files>backend/src/audio_video_search_backend/api/search.py, backend/tests/test_search_tiers.py, backend/tests/test_api_routes.py</files>
  <behavior>
    tiered({A: [(0.9, 1000), (0.8, 2000), (0.7, 3000), (0.6, 4000)], B: [(0.95, 500)]}) ergibt Dateireihenfolge B, A (bester Score) und Folge B@500, A@1000, A@2000, A@3000, A@4000.
    Nur eine Datei mit 8 Stellen: Folge enthält alle 8 in Score-Reihenfolge (Stufe 1 = 3, Stufe 2 = 3, Stufe 3 = 2), damit limit 5 genau 5 liefert (D-03-15).
    Gleichstand: zwei Dateien mit gleichem besten Score ordnen nach fileId aufsteigend; zwei Stellen mit gleichem Score nach Zeit aufsteigend.
    Präfix: für jede Datenlage aus den Testfällen ist Folge(limit=5) == Folge(limit=10)[:5] == Folge(limit=15)[:5].
    Offset: Vereinigung der Seiten [0,5), [5,10), [10,15) ist gleich Folge[:15], ohne Dublette; nextOffset = offset + Anzahl; hasMore true genau dann, wenn nach dem Schnitt noch Stellen folgen.
    Revision: Segmente einer Revision current-1 erscheinen nicht, wenn für dieselbe media schon Segmente der Revision current gefunden wurden (keine Mischung zweier Stände einer Datei); fehlt current ganz, keine Stelle.
    Stage: Probe -> "sample"; Level PREVIEW oder SELECTIVE -> "preview"; Level REFINED oder höher -> "final".
    Grenzen: offset < 0 oder > MAX_OFFSET (1200) und limit außerhalb 1..50 ergeben 422; leerer Begriff ergibt hits [] und hasMore false.
  </behavior>
  <implementation>SearchRequest um `offset: Annotated[StrictInt, Field(ge=0, le=MAX_OFFSET)] = 0` mit `MAX_OFFSET: Final = 1200` (Findling MAX_CONTAINER_OFFSET) erweitern. Neue Konstanten `PER_TIER: Final = 3`, `MAX_CANDIDATES: Final = 2000` (feste Kandidatenzahl unabhängig von limit und offset, sonst wäre die Folge nicht präfix-stabil). `admissible` umbauen: je media die höchste Revision aus {current, current-1} bestimmen, die unter den Kandidaten vorkommt, und alle Segmente genau dieser Revision zurückgeben. `tiered(stellen_by_file: Mapping[int, Sequence[tuple[float, int, str]]], per_tier: int = PER_TIER) -> list[tuple[int, int, str]]` wörtlich nach RESEARCH Code Example "Stufen-Folge". `_search(opened, term, offset, limit)`: Kandidaten `index.search(term, MAX_CANDIDATES)`, je media Stellen (Zeit wie heute erstes passendes Wort, sonst Segmentanfang; effective_words je media nur einmal laden), je file_id aus `store.file_ids_for_media` dieselben Stellen, dann tiered, Schnitt `[offset, offset + limit)`; Treffer zusätzlich `"stage"` nach behavior (Hilfsfunktion `stage_of(level: int) -> str`). Antwort `{"appVersion", "hits", "nextOffset", "hasMore"}`. test_api_routes.py nur anpassen, wo die alte Antwortform geprüft wird.</implementation>
</feature>
